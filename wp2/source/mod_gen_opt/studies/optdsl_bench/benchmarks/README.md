# OptDSL Benchmark Comparison Scripts

These scripts compare MiniZinc and LNS result quality on OptDSL benchmark instances.

## Available Scripts

- `benchmark_2dbp.py`
- `benchmark_jssp.py`
- `benchmark_cvrp.py`
- `benchmark_cvrptw.py`
- `benchmark_woodcutting.py`

Each script:
- runs `run_minizinc.py` for the MiniZinc backend
- runs the class-specific LNS runner under `studies/optdsl_bench/runners/`

## Size study: Small / Medium instance sets

`instance_sets.json` defines the Small and Medium sets per problem class used in
the computational study. To materialize the selected instances into
`output/size_sets/<class>/<set>/` and validate them with one short MiniZinc run
each:

```powershell
python studies/optdsl_bench/benchmarks/_prepare_size_sets.py --screen --solver gecode --timeout 60
```

Screening writes `output/size_sets/_summary.csv` / `.md` with per-instance solve
time, objective, and bound. The 2dbp Medium set includes size-scaled instances
(n=30/40/50) generated by `Tools/generate_2dbp_instances.py`.

> **Solver note:** use `--solver gecode` (the default). CP-SAT does *not*
> reliably honor `--time-limit` on the models generated from these DSLs and can
> keep running for many minutes past the budget; gecode terminates within the
> limit and reports objective + bound.
- writes a Markdown table and a CSV file

## Quick Start

```powershell
python studies/optdsl_bench/benchmarks/benchmark_jssp.py --files problem_instances/jssp/jssp_2x2.dsl
```

```powershell
python studies/optdsl_bench/benchmarks/benchmark_cvrp.py --files problem_instances/cvrp/benchmarks/golden_optdsl/Golden_1.dsl
```

## Notes

- The output reports result quality and runtime for both MiniZinc and LNS.
- MiniZinc bound is reported when available from the solver output.
- `benchmark_cvrptw.py` and `benchmark_woodcutting.py` expect benchmark directories that are not yet confirmed in the current repository layout.

## Warm-Start Workflow

The benchmark can save each instance's final best LNS solution as a DSL file
containing the original DSL plus a `@warm_start` decorator with the assignment
hints, and optionally run MiniZinc on that warm-started DSL to obtain a tighter
bound. This yields a 3-way comparison: MiniZinc vs LNS vs MiniZinc-with-warmstart.

### Flags

- `--save-warmstart` — Save each instance's final best LNS solution as a DSL
  snapshot with a `@warm_start` decorator. Files are written to `--warmstart-dir`
  (default: sibling subdir of the Markdown output, e.g.
  `output/benchmark_2dbp_study_warmstart/`). Each file is named
  `<instance>.warmstart.dsl`.
- `--warmstart-dir <path>` — Override the warm-start snapshot directory.
- `--mz-warmstart` — Run MiniZinc on each instance's warm-started DSL snapshot
  in addition to the plain MiniZinc run, and report the result as extra columns
  (`MZ+WS Quality`, `MZ+WS Bound`, `MZ+WS Time (s)`, `MZ+WS Gap (%)`). Implies
  `--save-warmstart`. Requires the LNS run (incompatible with `--skip-lns`).

### Examples

Save warm-start DSL snapshots only (no extra MiniZinc run):

```powershell
python studies/optdsl_bench/benchmarks/benchmark_2dbp.py --save-warmstart
```

Full 3-way comparison (MiniZinc vs LNS vs MiniZinc-with-warmstart):

```powershell
python studies/optdsl_bench/benchmarks/benchmark_2dbp.py --mz-warmstart
```

Run MiniZinc manually on a saved warm-start snapshot:

```powershell
python run_minizinc.py output/benchmark_2dbp_study_warmstart/<instance>.warmstart.dsl --timelimit 30 --solver cp-sat
```

### How it works

The LNS runner (`example_lns.py`) already supports `--emit-feasible-dsl <path>`
to write a DSL file with a `@warm_start` decorator built from the incumbent
assignment. The benchmark passes a per-instance path with no placeholders, so
the file is overwritten on each incumbent improvement and the final file
reflects the best solution. The MiniZinc translator parses `@warm_start`
decorators from DSL source and emits MiniZinc `warm_start(...)` solve
annotations plus objective bound constraints, so `run_minizinc.py` consumes the
warm-start info automatically with no extra glue code.
